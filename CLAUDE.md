# CLAUDE.md

Інструкції для Claude Code при роботі з цим репозиторієм.

## Про проєкт

Карта знань Data Science/AI на основі аналізу блогу DataCamp. Навчальний аналітичний проєкт, що демонструє повний цикл: збір даних → очищення → NLP-аналіз тем → побудова графа зв'язків → інтерактивна візуалізація → висновки.

Цільова аудиторія фінального продукту — початківці в Data Science, які хочуть зрозуміти структуру галузі та актуальні тренди.

## Структура репозиторію

- `scraping/` — скрипти збору даних (requests + BeautifulSoup4) з блогу DataCamp. Результат зберігати в `data/raw/`.
- `data/raw/` — сирі, необроблені дані (CSV/JSON). **Не комітити файли більші за 10MB.**
- `data/processed/` — очищені дані, готові до аналізу.
- `analysis/` — NLP-аналіз: TF-IDF, тематичне моделювання (LDA), кластеризація, NER. Результати (топіки, кластери) зберігати в `data/processed/`.
- `viz/` — побудова графа (networkx) та інтерактивної візуалізації (pyvis/D3.js/Streamlit).
- `notebooks/` — Jupyter notebooks для дослідження та прототипування; фінальний код переносити у відповідні `.py`-модулі.

## Технологічний стек

- Python 3.11+
- pandas, requests, BeautifulSoup4
- scikit-learn, gensim, spaCy або NLTK
- networkx, pyvis, plotly

Усі залежності фіксувати у `requirements.txt` з версіями (`pip freeze` або вручну з мінімальними версіями).

## Стандарти коду

- PEP8, type hints для публічних функцій
- Docstrings у форматі Google-style для всіх функцій/класів
- Функції — короткі, з однією відповідальністю; складну логіку розбивати на кілька функцій
- Змінні та коментарі в коді — англійською
- Коміти — англійською, формат [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `refactor:`, `data:`

## Робота з даними

- Дані завжди проходять шлях `raw/` → обробка → `processed/`; сирі дані ніколи не редагуються "на місці"
- Кожен скрипт обробки даних повинен бути ідемпотентним (повторний запуск не ламає результат)
- Для scraping: додавати затримку між запитами (`time.sleep`), поважати `robots.txt` сайту, обмежувати частоту запитів
- Не зберігати особисті дані чи будь-яку інформацію, що виходить за межі публічного контенту блогу

## Заборонено

- Хардкодити API-ключі чи токени — використовувати змінні середовища (`.env`, доданий у `.gitignore`)
- Комітити сирі HTML-сторінки чи датасети великого обсягу
- Агресивний/паралельний scraping без обмеження швидкості запитів
- Видаляти чи перезаписувати файли в `data/raw/` без явного запиту користувача

## Типовий робочий процес

1. Завдання ставиться через GitHub Issue з описом очікуваного результату
2. Claude створює окрему гілку (`feature/<short-description>`)
3. Реалізує зміни, додає короткий docstring/коментар з поясненням підходу
4. Комітить зі змістовним повідомленням і відкриває Pull Request
5. PR лишається на рев'ю користувача перед мержем у `main`

## Тестування

Для скриптів обробки даних та аналізу — додавати прості перевірки (напр. `assert` на форму DataFrame, відсутність NaN у критичних колонках) безпосередньо в код або в `tests/`, якщо обсяг проєкту виправдає окрему тестову структуру.
