# scraping/

Скрипти для збору даних з блогу DataCamp.

## Призначення

Зібрати публічні метадані статей блогу: заголовок, дату публікації, автора, теги/категорії, короткий опис (excerpt), URL. Повний текст статей **не** завантажується.

## Файли

- `fetch_articles.py` — єдиний скрипт: обхід пагінації, парсинг сторінок статей, запис CSV.

Окремих `parse_article.py` і `config.py` немає: логіка компактна, а налаштування — константи на початку модуля плюс прапорці CLI.

## Запуск

```bash
pip install -r requirements.txt

python tests/test_fetch_articles.py                      # офлайн-перевірка парсера
python scraping/fetch_articles.py --pages 2 --verbose    # тестовий прогін
python scraping/fetch_articles.py --pages 20             # повний збір
```

| Прапорець | Опис |
|---|---|
| `--pages N` | скільки сторінок списку обійти (типово 2) |
| `--start-page N` | з якої сторінки почати |
| `--limit N` | максимум статей за прогін |
| `--no-details` | зібрати лише URL, не відкриваючи сторінки статей |
| `--delay-min` / `--delay-max` | межі затримки між запитами (нижче 1 с не опускається) |
| `--output` | шлях до CSV (типово `data/raw/articles_raw.csv`) |
| `-v` / `--verbose` | докладний лог: з якого рівня взято теги, скільки посилань на сторінці |

## Як витягуються теги

DataCamp — застосунок на Next.js. Сторінка статті гідратується на клієнті з JSON у
`<script id="__NEXT_DATA__" type="application/json">`. **Тегів статті немає ні в HTML, ні в
`<meta>`, ні в JSON-LD** — усі посилання на `/category/` та `/tag/` у розмітці належать
глобальному меню сайту, а не статті. Саме звідси в ранній версії бралися ~70 однакових
значень на кожен рядок плюс склеєне `See MoreRight Arrow`.

Метадані витягуються чотирма рівнями, перемагає перший непорожній:

| Рівень | Джерело | Що дає |
|---|---|---|
| 0 | `__NEXT_DATA__` → `props.pageProps.page` | **теги** (`category.tag` + `subCategories[].tag`); резервно title/date/author |
| 1 | JSON-LD `BlogPosting`/`Article` (з `@graph`) | title, date, author, excerpt |
| 2 | `<meta>` (`og:*`, `article:*`) | title, date, author, excerpt, `article:tag` |
| 3 | HTML-евристики (`<h1>`, `<time datetime>`, `[rel=author]`) | те саме як остання надія |

Приклад для `/blog/gemini-3-7-flash`:

```json
"category":      {"id": 16,  "tag": "Artificial Intelligence",  "slug": "ai"},
"subCategories": [{"id": 204, "tag": "Large Language Models", "slug": "large-language-models"}]
```
→ `tags = Artificial Intelligence|Large Language Models`

**Перевірка на розмір застосовується до всіх чотирьох рівнів**: список довший за 12 тегів
відкидається цілком, а не обрізається — обрізання тихо лишило б неправильні значення й
виглядало б як успіх. Якщо жоден рівень не дав тегів, колонка лишається порожньою; глобальне
меню туди не потрапляє ніколи. Додатково `validate_rows()` падає **перед** записом CSV, якщо в
рядку опинилося більше 12 тегів — щоб регресія не потрапила у файл непоміченою.

Якщо на сторінці списку взагалі немає посилань `<a href="/blog/...">` (повністю клієнтський
рендеринг), посилання відновлюються з того ж `__NEXT_DATA__` — по об'єктах, що мають одночасно
`slug` і `title`.

## Правила

- `robots.txt` завантажується на старті й парситься через `urllib.robotparser`; **кожен** URL
  перевіряється через `can_fetch()` перед запитом. Якщо файл недоступний — скрипт відмовляється
  сканувати взагалі, а не «продовжує про всяк випадок».
- Директива `Crawl-delay` перекриває локальну затримку, якщо вона більша.
- Випадкова затримка 1–2 с між послідовними запитами.
- Обробка помилок: до 3 спроб з backoff (2 с, 4 с) на timeout/429/5xx; 404 — пропуск без
  повторів; явні попередження при зміні структури сторінки.
- Ідемпотентність: результат мержиться з наявним CSV і дедуплікується за `url` (свіжіший запис
  перемагає), перед записом — `assert`-перевірки.
- Описовий User-Agent із посиланням на репозиторій. Сирі HTML-сторінки не зберігаються.

## Колонки результату (`data/raw/articles_raw.csv`)

| Колонка | Опис |
|---|---|
| `title` | Заголовок статті |
| `url` | Канонічне посилання (без query і фрагмента) |
| `published_date` | Дата публікації, `YYYY-MM-DD` |
| `author` | Автор (якщо доступно) |
| `tags` | Теги статті, роздільник `\|` |
| `excerpt` | Короткий опис (до 500 символів), **не** повний текст |
| `scraped_at` | Дата збору, `YYYY-MM-DD` |

Відхилення від початкового плану:

- додано `scraped_at` — відстеження свіжості даних при повторних запусках;
- `tags` — рядок з роздільником `|`, а не список: CSV не має типу «список».
  Для аналізу: `df["tags"].str.split("|")`;
- пропущені значення пишуться порожнім рядком, а не `NaN`.

## Тести

`tests/test_fetch_articles.py` — офлайн-перевірки на HTML-фікстурах, без мережі. Ключові фікстури:

| Фікстура | Що перевіряє |
|---|---|
| `GEMINI_PAGE_PROPS` | реальна структура `__NEXT_DATA__` → рівно `["Artificial Intelligence", "Large Language Models"]` |
| `SITE_WIDE_CATEGORY_MENU` | 70 категорій + обидва варіанти `See More` (звичайний і зі спаном-іконкою) — не потрапляють у теги |
| `BLOATED_JSONLD` | `keywords` із 70 значень відкидається на розмірі |
| — | відсутній / зламаний / без `props.pageProps.page` `__NEXT_DATA__` → фолбек на meta |
